# R75：逐块回退（c）与 Thunderbird 进化（d）——预注册设计

写于 2026-09-27 15:40 UTC，在看到任何 R75 结果之前。之后如有改动，只追加"变更记录"，不改下面的原文。

## 背景（已有事实）

- 主版本（pool：5 次合成 + 质量门 + 跨合成挑选）在 Thunderbird 上是 64.86×，DeLog 实测 67.68×。
- 逐块对账：第 0 块上 pool 比 DeLog 小 0.9%；但同一个月（11 月）剩下的 89 块已经大 6.0%。全文件 2,113 块里有 1,420 块比 DeLog 大。语义存档 26.97 MB，只让骨干部分少了 6.6 MB。
- 用已有逐块字节估算"每块取 min(pool, DeLog)"：Thunderbird 68.26×，总字节 −3.34%。这只是估计，前提是空程序路径和 DeLog 同字节；R56 旧运行时里空程序块比 DeLog 大 1.4%。

## (c) 逐块回退（per-block backbone fallback）

- **规则**：每块在线编码两次，一次用部署程序，一次用空程序（只走残余/骨干路径），保留完整块载荷更小的那个，并在存档里记录选择。只用当前块，不看未来，不针对数据集。
- **(b) 先实测**：在 Thunderbird（第 1、101 块及留出样本块）、Spark、HPC、OpenSSH 的若干块上，测空程序载荷相对上游 DeLog 逐块字节的开销，以及回退能省多少。
- **主结果**：如果实测开销小、收益为正，就对 16 个文件跑正式压缩、独立解码、SHA 审计和同会话计时（版本名 `pool_fb`）。编码时间照实计入两次编码。
- 结果无论正负都如实记录；主结果是否换成 `pool_fb`，看正式数字。

## (d) Thunderbird 进化（R75-EVO）

- **窗口（预注册）**：先做筛选窗口，Thunderbird 第 0–99 块（前 1,000 万行）。
  - **继续条件**：未来块上相对"冻结 + 回退"基线省 ≥1% 字节，就扩展到全文件 2,113 块；扩展后报告全文件结果，不再只报窗口。
  - **未达标**：报告窗口结果，作为负面/中性结果，并注明窗口范围。
- **基线**：冻结的 pool 程序 + 逐块回退 (c)。
- **程序库**：P 起初只有第 0 块训练的 pool 程序，空程序始终可用。每块用 P 中所有程序和空程序各编码一次，取最小。这是 (c) 的推广，只用当前块。
- **触发**：第 b 块完成后（b ≥ 1）看最近 5 个已完成块（不足 5 块时至少 3 块）。满足以下全部条件就触发一次更新：
  - 有 ≥3 块"输给骨干"，即最佳已发布程序比空程序省不到 1%，或直接选了空程序；
  - 距上次发布 ≥10 块；
  - 更新尝试次数未到上限。
- **更新**：用第 b 块（最近完成的块）做训练块，走和主版本完全相同的流程：5 次合成（T=0 一次 + T=0.7 四次）→ 质量门 → 跨合成挑选 → 存储拟合。
- **验证**：候选程序在第 b+1 块上，要比当前程序库（含空程序）的最小值再小 ≥1%，才发布。发布从第 b+2 块起生效；已写好的块不改。
- **上限**：最多发布 5 次，最多尝试 8 次；被拒后冷却 10 块。
- **主要指标**：第一次发布之后的未来块上，进化 vs 冻结 + 回退的总字节。
- **次要指标**：
  - 窗口总字节，对比冻结无回退、冻结 + 回退、进化、上游 DeLog 四种；
  - API 次数、合成与挑选时间、逐块编码时间。
- **正式性**：最终数字要把实际选中的逐块载荷拼成存档，用只看存档的解码器独立解码，并核对 SHA。
- **边界**：筛选窗口只有 100 块，而 Thunderbird 的格式漂移主要在更后面的月份。所以窗口内的收益主要来自"第 0 块不具代表性"，不是长期漂移。这一点要写进报告。

## 变更记录

- **2026-09-27 16:30 UTC，(b) 实测，出于代码结构的发现，在任何 R75-EVO 结果之前记录。**
  - SemZip 自己的空程序骨干，在 Thunderbird 上比上游 DeLog 大 5.6%–18.9%。原因是上游 DeLog 为 16 个 LogHub 数据集都手写了按数据集名选择的正则（`compressor.cpp` 的 `regex_map`），Thunderbird 那条覆盖 `HH:MM:SS` 和 `YYYY.MM.DD`；SemZip 的骨干分支关掉了这些。
  - 所以按规则（不用数据集专用规则）实现的 (c)，只能回退到 SemZip 自己的空程序。10 块抽样里只省 0.22%。
  - 回退到上游 DeLog 块虽然能让 Thunderbird 反超（离线估算 68.19×），但等于拿基线做逐块集成，还引入了手写的数据集专用正则，违反研究规则，因此不做。
  - (c) 只做实测记录，不进主方法（待确认）。R75-EVO 的基线相应改为"冻结 pool + 逐块取 min(pool, 空程序)"，和原设计一致。
